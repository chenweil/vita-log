# 轻盈计划 #06.1：Cloudflare 实时公开读取与服务端编辑授权

Status: ready-for-agent

这是第一版独立 Web 应用的部署扩展 spec。它保留 #01–#08 已完成的健康数据模型、导入导出和仓库契约，把 Cloudflare 部署下的公网读取与编辑授权收敛为服务端边界。它覆盖 `.scratch/independent-web-v1/issues/06.1-realtime-public-read-server-auth.md` 的全部决定。

## Problem Statement

原 #06 通过手动生成 JSON 文件提供只读分享。该模型适合静态快照，但访客看到的不是服务端当前数据；本人每次修改后都必须重新生成和部署发布文件。新的目标是让访客访问页面时读取当前已保存数据，同时只有本人完成密码登录后才能编辑。前端显示“编辑状态”不能承担安全责任，所有写操作必须在服务端再次授权。

当前 #08 的实现是 Node.js + 本机 SQLite。它适合本地自托管，但不能直接作为 Cloudflare Pages 的公网运行时。Cloudflare 部署需要把在线事实来源、请求授权、会话和故障行为重新落到 Pages Functions 与 D1 边界上。

## Solution

使用 Cloudflare Pages 承载现有 Vite 静态前端，使用同源 Pages Functions 提供 API，使用 Cloudflare D1 保存唯一在线事实快照。未登录访客读取当前 D1 快照并保持只读；本人通过服务端密码会话后获得限时编辑能力。保存成功后，访客下一次刷新从 D1 读取最新数据，不生成或上传发布 JSON。

本机 SQLite 不作为公网在线主库。完成迁移后它保留为离线备份和恢复副本；系统不双写，也不把两个存储当作可互相覆盖的事实来源。#06 的 JSON 快照分享继续保留为独立的非实时分享功能。

## User Stories

1. 作为访客，我希望无需登录即可打开页面并看到当前已保存的健康看板，以便查看最新状态。
2. 作为访客，我希望刷新页面后看到本人最近一次成功保存的数据，以便不依赖手动发布文件。
3. 作为访客，我希望看到昵称、体重/体脂、围度、步数、打卡、饮食明细和备注，以便完整理解当前看板。
4. 作为访客，我不希望看到密码摘要、会话标识、备份文件、内部存储元数据或其他认证材料，以便公开读取不泄露内部状态。
5. 作为访客，我希望在服务不可用时看到明确的不可用提示，以免把故障误读为空数据或旧数据。
6. 作为本人，我希望通过密码登录后开启编辑状态，以便在共享公开页面上维护记录。
7. 作为本人，我希望未登录、锁定或会话到期时页面恢复只读，以便编辑权不会长期留在浏览器中。
8. 作为本人，我希望保存、删除、导入、清空、迁移、备份和恢复都由服务端验证，以便绕过页面控件也不能写入。
9. 作为本人，我希望登录失败受到限流，以便密码接口不容易被暴力尝试。
10. 作为本人，我希望锁定和注销立即撤销会话，以便已打开的页面不能继续写入。
11. 作为本人，我希望首个管理员不会被公网访客抢先创建，以便首次部署仍由我控制。
12. 作为本人，我希望忘记密码时通过 Cloudflare Secret 或运维命令离线重置，以便不开放危险的公网找回接口。
13. 作为本人，我希望登录会话使用安全 Cookie 和同源请求约束，以便降低会话窃取和跨站写入风险。
14. 作为本人，我希望 D1 首次迁移前看到来源、各类数量、日期范围、营养汇总、设置摘要和数据库是否为空，以便确认迁移影响。
15. 作为本人，我希望 D1 非空时拒绝自动迁移，以便不会静默覆盖在线事实数据。
16. 作为本人，我希望迁移前完成代表性数据对账和完整 JSON 备份，以便切换后仍能恢复。
17. 作为本人，我希望 D1 成为唯一在线事实来源，以便不会出现本机 SQLite 与 D1 双写冲突。
18. 作为本人，我希望定期导出完整 JSON 并保留本机 SQLite 副本，以便 D1 故障或误操作后可以离线恢复。
19. 作为维护者，我希望写操作记录最小审计事件，以便追踪时间、操作类型、结果和版本，同时不复制健康数据内容。
20. 作为维护者，我希望健康 API 禁止 CDN 缓存，以便“刷新看到最新保存数据”的语义不会被旧缓存破坏。
21. 作为维护者，我希望保留 #06 的静态 JSON 分享路径，以便在不需要实时数据时仍可使用文件型只读分享。
22. 作为维护者，我希望 Cloudflare 预览环境和生产环境都能验证匿名读取、未授权写入、会话失效、CSRF、限流、迁移和故障行为，以便公网发布有可重复的验收证据。

## Implementation Decisions

### Runtime and authority

- Cloudflare Pages 提供静态前端；同源 Pages Functions 提供动态 API；D1 是唯一在线事实来源。
- 本机 SQLite 仅作为迁移来源、离线备份或恢复副本；不双写、不在线镜像、不自动合并。
- D1 API 的健康数据响应使用 `Cache-Control: no-store`。保存成功后，访客下一次刷新读取 D1 最新快照；不做 WebSocket 或主动推送。
- D1 或 Pages Functions 故障时 fail-closed：显示明确不可用状态，不回退旧 CDN 缓存、本机 SQLite 或空快照。

### Public and owner capabilities

- 公共读取响应包含昵称、体重/体脂、围度、步数、打卡、饮食明细和备注。
- 认证、会话、备份、内部存储元数据和其他内部字段不能进入公共响应。
- 未登录状态永远只读。前端控件隐藏只是体验层；服务端对每个写请求独立检查会话。
- 写请求覆盖新增、修改、删除、导入、清空、迁移、备份和恢复。
- #06 的 JSON 发布快照仍是独立的静态非实时分享模式。

### Deployment and initialization

- 部署优先级为 Cloudflare；首期采用 Pages + Pages Functions + D1，不采用独立 API 域名，也不开放 CORS。
- 首个管理员由部署时 Cloudflare Secret 或一次性运维命令预置。公网没有 setup、注册或密码找回入口。
- 密码遗失只能通过 Cloudflare Secret/运维命令离线重置。
- 生产部署要求 HTTPS。Pages Functions 运行在 Web Crypto 兼容环境，不直接依赖 Node `scryptSync`。

### Password, session and request security

- 密码摘要使用 Web Crypto PBKDF2-HMAC-SHA-256，210,000 次迭代，保存独立盐、迭代次数和摘要。
- 编辑会话 30 分钟绝对过期；锁定和注销立即撤销服务端会话。
- 会话 Cookie 必须使用 `HttpOnly`、`Secure`、`SameSite=Strict`。
- 写请求强制检查 `Origin/Host`，不开放跨域 CORS。
- Cloudflare Rate Limiting/WAF 与 Worker 内部按账号/IP 双层限流。
- 服务端返回稳定的未授权、版本冲突、验证失败、数据库不可用和迁移冲突错误码。
- 每次写入保留最小审计事件：时间、操作类型、结果和版本；不记录健康数据内容。

### Migration, backups and recovery

- D1 首次迁移要求数据库为空。
- 迁移预览展示来源、各类型数量、总数、日期范围、营养汇总、设置摘要和 SQLite/D1 是否为空。
- 迁移必须由本人确认；确认前不改变 D1；对账和完整 JSON 备份完成前不开放公网读取。
- D1 迁移完成后成为唯一在线事实来源；本机 SQLite 和完整 JSON 为离线恢复材料。
- D1 使用平台恢复能力；定期导出完整 JSON 到受限离线位置，并保留本机 SQLite 副本。
- D1 非空时拒绝自动迁移；替换或合并必须走明确的导入策略和版本检查。

### Module and interface boundaries

- 前端继续使用应用级健康数据仓库接口；D1 仓库适配器替换存储实现，不改变领域计算和页面规则。
- Pages Functions API 负责读取、认证、写入、迁移预览、备份、恢复和审计事件入口。
- D1 载荷保持版本化完整 `HealthSnapshot` 结构，不重新拆分成第二套业务模型。
- Node + 本机 SQLite 的代码保留为离线迁移/备份工具，不作为 Pages Functions 运行时依赖。
- 纯静态 `localStorage` 运行模式转为只读：它可以查看和导出本地数据，但不再提供编辑入口，也不再加载源码内置的默认账号、盐或密码摘要。编辑统一进入 Cloudflare D1/Pages Functions 模式。
- 历史上已经进入公开 Git 历史的编辑凭据视为已暴露材料；修复必须同时轮换密码、移除源码配置，并在确认远端策略后重写历史和强制推送。

## Testing Decisions

- 主要浏览器 seam 是完整页面对健康数据仓库契约的公开 UI 行为；测试访客只读、登录后编辑、会话到期、注销和刷新可见数据。
- Pages Functions seam 测试匿名 GET、未授权写入、正确会话写入、版本冲突、CSRF/Origin、限流、初始化抢占、稳定错误码和 no-store 响应。
- D1 repository contract 测试空库、有效快照、原子写入、重复/过期版本、迁移非空拒绝、备份、恢复和故障 fail-closed。
- 迁移 seam 测试预览数量、类型、日期、营养汇总、设置摘要、确认前不变和确认后完整导入。
- 安全测试不把“按钮隐藏”当作授权证据；必须直接调用 API 验证未授权写入被拒绝。
- Cloudflare preview/production smoke 测试覆盖匿名读取、本人登录、写入后访客刷新、会话失效、注销、限流、初始化和 D1 故障。
- 现有本地模式、#06 静态快照和 #08 Node SQLite 测试继续运行，作为迁移和兼容回归。

## Out of Scope

- 多用户账户、注册、角色、协作编辑和第二位编辑者。
- 邮箱密码找回、MFA、TOTP、Passkey；可作为后续安全增强单独设计。
- 独立 API 域名、开放跨域客户端和第三方客户端 SDK。
- WebSocket/实时推送；实时含义是本人保存后访客下一次刷新读取最新数据。
- 公开字段配置 UI；本 spec 固定公开字段集合。
- D1 与本机 SQLite 双写、自动同步或按更新时间静默合并。
- Supabase、其他云数据库和多云故障切换。
- 在 D1 中保存完整变更前后健康快照审计副本。
- 医疗诊断、健康数据加密产品化和第三方健康平台接入。
- 在纯静态 `localStorage` 模式继续提供编辑能力或构建期注入本地编辑密码。

## Further Notes

- 该 spec 是第一版本地优先 spec 的 Cloudflare 公网扩展；它覆盖 Cloudflare 在线部署，不改变 #01–#06 的本地模式和静态快照能力。
- “所有人可查看”是健康数据公开决策，不等于认证、备份、会话或内部状态公开。
- 设计收敛不等于公网安全通过。Cloudflare Secret、D1 数据库、Pages Functions、Rate Limiting/WAF、DNS/HTTPS 和离线备份必须在部署时用 `/wizard` 处理，并在生产环境取得证据后才能关闭 #06.1。
