# 06.1-01: D1 实时公开读取与公共投影

**What to build:** 让未登录访客通过同源 Pages Functions 读取 D1 当前在线快照，看到完整健康看板；响应不泄露认证、会话、备份或内部存储状态，并在 D1 不可用时显示明确错误。

**Blocked by:** None (can start immediately)

**Status:** done

- [x] D1 保存版本化完整 `HealthSnapshot`，公共响应投影昵称、体重/体脂、围度、步数、打卡、饮食明细和备注，以及渲染完整看板所需的 display-facing settings（性别、年龄、身高、起始/目标体重、目标体脂、活动系数、营养目标、训练计划和习惯）；不投影认证、会话、备份或内部元数据。
- [x] `GET` 读取不要求登录，响应使用 `Cache-Control: no-store`，不包含密码摘要、会话、备份或内部元数据。
- [x] 移除本机 `127.0.0.1` hostname 假设，Pages Functions 可以处理 Cloudflare 公开域名。
- [x] D1/Function 失败时返回稳定数据库不可用错误；页面不回退旧缓存、本机 SQLite 或空快照。
- [x] API contract tests 覆盖匿名读取、公开字段投影、敏感字段排除、no-store 和故障响应。

### 逐条验收证据

**① 版本化完整快照 + 公共投影**
- `functions/schema.sql` 定义 `health_state(id=1, payload, version, saved_at)`，承载完整 `HealthSnapshot`。
- `src/public-snapshot.ts:projectSettings` 投影 15 个 display-facing 字段（昵称/性别/年龄/身高/起始与目标体重/目标体脂/活动系数/5 项营养目标/训练计划/习惯）；`createPublicSnapshot` 对 5 类记录逐字段复制。
- 主题色 `primaryColor`/`accentColor` 未投影：`src/app.ts` 渲染路径只把 `'primary'`/`'accent'` 当 CSS 变体名使用，从不读取这两个字段（grep 确认仅存在于 `src/domain.ts`）。
- 证据：`tests/public-snapshot.test.ts`「投影昵称、五类记录与备注」「投影渲染完整看板所需的 display-facing settings」「不投影主题色、认证、会话、备份或内部元数据」「丢弃投影外的附加字段，即使它们挂在快照顶层」。

**② 匿名 GET + no-store + 无敏感字段**
- `handlePublicSnapshot` 不读取任何凭据即返回 200；成功与失败响应都带 `cache-control: no-store`。
- 公开响应体只有投影本身，**不含** `version`/`saved_at`（这两者属「内部存储元数据」；版本化写路径在 06.1-02a/03 才需要）。
- 证据：`tests/d1-public-api.test.ts`「未登录访客可读取完整看板」「响应使用 Cache-Control: no-store」「公开响应不含密码摘要、会话、备份或内部存储元数据」。

**③ 移除 127.0.0.1 假设**
- 删除 `server/api.ts` 的 `url.hostname !== '127.0.0.1'` 拒绝；所有校验改为相对请求自身 origin。
- 自托管 Node 进程的 loopback 姿态保留在监听层：`server/main.ts:39` 绑定 `127.0.0.1`，`server/main.ts:13-14` 在进入 API 前拒绝不匹配的 `Host` 头。请求层因此不再假设 loopback 部署。
- 证据：`tests/d1-public-api.test.ts`「可以处理 Cloudflare 公开域名，不假设 127.0.0.1」；`tests/sqlite-api.test.ts`「不以 loopback hostname 白名单拒绝请求，但写入仍要求同源」。

**④ 故障 fail-closed**
- 缺绑定 / 查询抛错 / 载荷损坏 → `503 database-unavailable`，**不**返回空快照（`readHealthState` 一律 raise）。
- 空库（本人尚未导入）→ 同样 503 + 独立文案「D1 尚未导入健康数据…」，错误码沿用 spec 定义的 5 个码，不新增第 6 个。
- 浏览器侧：传输失败、非 2xx、无法解析的响应体全部抛 `StorageError`；`load()` 只发一次请求，不回退旧缓存/本机 SQLite/空快照。
- 证据：`tests/d1-public-api.test.ts`「D1 查询失败时返回稳定 database-unavailable」「缺少 D1 绑定时同样 fail-closed」「空库（尚未导入）不会被伪装成空健康数据」「损坏的 D1 载荷不会被降级为空快照」；`tests/d1-client.test.ts` 对应用例。

**⑤ API contract tests**
- 新增 3 个文件 + 扩写 1 个，共 27 个新用例：`tests/public-snapshot.test.ts`(7)、`tests/d1-public-api.test.ts`(11)、`tests/d1-client.test.ts`(8)、`tests/sqlite-api.test.ts`(+1)。全套 `77 passed (16 files)`（改动前 50）。
- `tests/d1-public-api.test.ts` 的 FakeD1 会统计 SQL 占位符数量，多绑/少绑即抛错——真实 D1 对多余绑定会报错，此前 fake 完全忽略 `bind()` 才让该缺陷隐形。

### 变异验证

投影与 fail-closed 断言逐个打过变异体，确认不是恒绿：

| 变异 | 结果 |

| 响应去掉 no-store | 红 |
| 直接返回 owner 快照不投影 | 红（2 处） |
| 查询改回 `WHERE id = 1` 仍 `.bind(1)` | 红（6 处） |

三次「变异后仍绿」经复查都**不是覆盖缺口**：一次 perl 替换实际未命中（空操作变异）；一次让缺绑定返回**结构非法**的空快照（被下游 `normalizeSnapshot` 拒绝，故 GREEN 是正确答案）；一次 fixture 写了 `saved_at: 'whenever'`（仍是字符串，变异未被真正破坏）。改用结构合法/真正破坏的靶子后均转红。

补测两处真实缺口：错误码白名单无覆盖（已加「未知或伪造代码降级为 database-unavailable」）、`saved_at` 无关性未被真正钉住（fixture 改为整行不带该列）。

### /code-review 结果与处理

双轴审查（Standards / Spec）各派一个只读子代理，固定点 `39443d2`。已处理：

| 发现 | 处理 |
| --- | --- |
| `.bind(1)` 配 `WHERE id = 1`，多绑一个未引用值 | 改 `WHERE id = ?`；fake 增加占位符计数以覆盖此类回归 |
| `D1SnapshotRow.version`/`savedAt` 校验后被丢弃，且坏 `saved_at` 会把可读快照变成 503 | 删掉包装类型，`readHealthState` 直接返回 `HealthSnapshot`，只读 `payload`；加测试钉住该无关性 |
| 公开 settings 字段名在三处各写一遍（漏一处即静默投影错） | `PUBLIC_SETTING_KEYS` 单一来源；`PublicHealthSettings` 由 `Pick` 派生；两个方向共用 `publicSettings()` |
| 敏感词用小写 `'version'` 子串断言，恰好被 `publicSchemaVersion` 绕过 | 改为字段级断言：顶层与 `settings` 的精确键集合 + 定向子串 |
| 非 GET 落到平台默认 405（text/plain、无 no-store、非稳定码） | 新增 `onRequest` 统一返回 `405 validation-failed` + no-store |
| `isRecord` 两份且语义已分叉 | 复用 `src/domain.ts` 中更严格的那份（改为导出），删掉本地副本 |
| 移走 hostname 检查后 ADR-0001 未记录 | ADR-0001 补一段：边界由监听层承担，指向 ADR-0002 |

复核后**不做**的（附理由）：`Fetcher` 局部类型名与 `src/sqlite-storage.ts:6` 的既有写法一致，保留一致；三个 `ownerSnapshot` fixture 字段集本就各不相同（5/2/1 类记录），抽公共 helper 反而强制它们相同；为两个只读方法抽基类属投机泛化。
