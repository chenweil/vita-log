# 06.1-06: Cloudflare 生产部署与切换验收

**What to build:** 将已验证的 Cloudflare Pages + Pages Functions + D1 实现部署到生产，完成 Secret、D1、迁移、备份和公网安全验收，使访客实时读取和本人服务端编辑可在真实域名运行。

**Blocked by:** 06.1-01, 06.1-02a, 06.1-02b, 06.1-03, 06.1-04, 06.1-05

**Status:** ready-for-human

- [ ] Cloudflare Pages、Pages Functions、D1 绑定和 HTTPS 自定义域名已由本人完成配置。
- [ ] 首个管理员通过 Secret/一次性运维命令预置，公网 setup、重置和跨域写入均关闭。
- [ ] 本机 SQLite 到空 D1 的预览、对账、完整 JSON 备份和一次性导入完成。
- [ ] 匿名访客能读取最新 D1 看板；本人能登录、编辑、注销，访客刷新能看到保存结果。
- [ ] **Workers 套餐的 CPU 额度已确认足以完成 210,000 次 PBKDF2 登录校验**，并在 Cloudflare 预览环境实测过一次登录的真实耗时。若不足，套餐升级或下调迭代数都是可接受的选择，但必须是一次**有记录的显式决策**，不能等到公网登录超时才发现。（由 #06.1-02a 第四轮复核发现：该项此前只写在 02a 的边界说明里，无票据承接）
- [ ] 生产环境通过会话到期、CSRF、限流、初始化抢占、备份泄露、版本冲突和 D1 故障 fail-closed 验收。
- [ ] Cloudflare preview/production、桌面/移动浏览器和回滚路径均有证据记录。
- [ ] 按 `docs/d1-backup-recovery.md` 应用审计增量迁移，配置受限离线目录与定期 JSON/SQLite 导出；取得一次恢复前备份、版本冲突拒绝以及 Time Travel 恢复/撤销历史会话的目标环境证据。定时任务模板见 `ops/d1-backup.launchd.plist.example`。
- [ ] 预览环境核对 D1 batch 内实际写入与审计结果、unknown/not-initialized、迁移旧行保留、分类分页和独立清理上限；平台限流覆盖备份/导出路径，不能以单 isolate 的本地测试替代跨 isolate 验收。
- [ ] 只有本人执行的 Cloudflare 控制台、Secret、D1 创建和备份配置步骤通过 `/wizard` 完成，不由 agent 猜测或代填。
