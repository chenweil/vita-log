**Blocked by:** 06.1-01: D1 实时公开读取与公共投影

- [x] 纯静态 `localStorage` 模式改为只读，不再加载 `DEFAULT_EDITOR_AUTH`、用户名、盐或密码摘要。
- [x] 已发布的历史凭据材料完成密码轮换；当前工作树和新构建产物不包含硬编码编辑凭据。

## 交付说明

公网上唯一的账号创建入口被**删除**，而不是加开关：留着但拒绝的引导路由，距离「接受」只差一次配置改动。两个后端都不再有任何 setup/注册/找回路由，轮换改由运维命令承担。

| 文件 | 变更 |
| --- | --- |
| `server/api.ts` | 删除 `/api/setup` 分支；`/api/login` 只做登录。两个匿名 GET 不再回显 `configured` |
| `src/server-auth.ts` | 删除 setup 回退**和** `allowSetup` 选项本身，恒定请求 `/api/login` |
| `server/store.ts` | 新增 `setOwnerCredentials()`（运维轮换用）；`setup()` 仍在重复调用时抛错 |
| `server/owner-cli.ts`（新） | 运维命令：预置/轮换本机 SQLite，或生成 Cloudflare Secret 值 |
| `scripts/credential-scan.mjs`（新） | 凭据材料扫描器：源码按标识符形状，产物按值形状 |
| `scripts/verify-release.mjs` | 产物纳入凭据扫描；资源引用检查改为兼容子路径构建 |
| `.github/workflows/pages.yml` | 构建后执行 `node scripts/verify-release.mjs`，让产物保证进入 CI |
| `tests/bootstrap-closure.test.ts`（新） | 初始化封闭、只读静态模式、未授权写入复验 |
| `tests/credential-scan.test.ts`（新） | 扫描器正/负例、压缩产物形态、每条模式都有触发样本 |

## 验收证据

**① 公网无 setup/注册/找回，首个管理员只能离线预置**

`tests/bootstrap-closure.test.ts` 同时检查匿名与**已登录**两种身份：匿名拿到 401/404 已登录拿到 404，两者合并才证明分支被删除而不是被门控——只测匿名无法区分「删除」与「拒绝」。`store.credentials()` 在两次请求后仍是 `null`。注册/找回/重置五个路径逐一 POST 与 PUT，均未创建账号。`functions/api/` 只有 `login`、`logout`、`session`、`snapshot` 四个文件。客户端侧 `src/` 无 `/api/setup` 代码引用（唯一 grep 命中是 `server-auth.ts` 的说明注释，剥注释检查已排除）。

**② 纯静态模式只读，不加载凭据**

`DEFAULT_EDITOR_AUTH` 在 `src/` `server/` `functions/` 中 0 命中（仅存在于守它的用例里）。`mountApp` 的默认认证是 `ReadOnlyEditorAuth`，实测 `isUnlocked()` 为 `false`；`main.ts` 的 localStorage 分支按括号配对取出**整个** `mountApp(...)` 调用，断言不含 `Auth` 且顶层参数恰为 2 个。

**③ 凭据轮换与残留**

工作树与源码扫描 0 命中；产物扫描在 `verify-release.mjs` 中执行，并已接入 CI（此前 CI 从不调用它，等于产物保证无人执行）。预置/轮换机制两种后端都有：`npm run owner -- cloudflare-credential` 生成 Secret 值，`npm run owner -- sqlite-set <username>` 预置或轮换本机库。

**运维命令端到端实跑**（本次当场执行）：

| 场景 | 结果 |
| --- | --- |
| `sqlite-set owner`（管道传密码） | 已预置账号 owner。 |
| 再次 `sqlite-set owner`（换密码） | 已轮换账号 owner。 |
| `sqlite-set owner <密码>` 从 argv 传 | 拒绝，退出码 1 |
| 6 字符短密码 | 拒绝（至少 12 字符），退出码 1 |
| `cloudflare-credential` | 输出 `pbkdf2-sha256$210000$…` |

轮换是否真的生效，用真实登录路径验证而非只看写入：**新密码登录 200，旧密码登录 401**。

**④ 未授权 setup、重复初始化、密码重置被拒；写授权复验**

`store.setup()` 对重复调用抛 `migration-conflict`「本人账号已经设置」（409）且不改写既有账号（纵深防御，HTTP 路由已不存在）。`06.1-02a` 的写授权在此复验：无会话写入 401、伪造 cookie 写入 401，且两种情况下已保存数据与版本均未变。

**⑤ 回归测试覆盖**

`tests/bootstrap-closure.test.ts`（12 条）覆盖初始化抢占、静态只读模式与直接 API 未授权写入；`tests/credential-scan.test.ts`（8 条）覆盖历史配置缺失（源码与产物均无凭据材料）。全套 `npx vitest run`：**149 passed / 22 files**（02b 之前为 129 / 20）。

**⑥ 刻意未执行的运维动作**

历史重写与两个远端的强制推送**未执行**。它不可逆且同时涉及 `origin`(cnb.cool) 与 `github` 两个远端，须先确认 clone 状态与远端策略。

已核验的事实（当场执行 `git cat-file --batch-all-objects` 取全部 213 个 blob 逐个按最严格的**值形状**扫描）：**不存在真实编辑凭据**。扫描器有 **2 处命中**，都在 `tests/d1-password.test.ts`（blob `62b98fa622`、`f6f9c78d67`），内容是合成测试盐 `000102030405060708090a0b0c0d0e0f`——该用例断言「非 210,000 次迭代必须被拒绝」，它不是凭据。**这里如实记下而非略过**：只写「零命中」会让下一个跑同一条扫描的人以为我漏了这两个文件。

因此改写历史目前没有安全上的紧迫性，应按部署计划择机执行，而不是在本票里顺手做掉。

## 边界说明

- **历史重写与强制推送未执行**，见验收 ⑥。承接方是本人，前置条件是 clone 状态与远端策略确认。
- **密码轮换由本人执行**（密码由本人选择）。本票交付的是机制与残留核验，不是替本人改密码。
- **轮换不会自动注销已签发的会话**。历史泄露的是 PBKDF2 摘要与盐——足以离线爆破出密码，但拿不到会话令牌；只有攻击者真的登录过，轮换才不足以把人请出去。因此 `npm run owner -- sqlite-set` 在轮换时会直接提示剩余步骤（本机 SQLite 会话在服务进程内存中，重启即全部失效；Cloudflare 部署改 Secret 后需另行清空 `owner_session` 表）。**没有为此新建会话吊销机制**：D1 侧要在每次请求上重算 PBKDF2 才能做到对称，代价正撞上 `06.1-02a` 记录的 Workers CPU 限额问题，而那一侧的正确答案是一次性运维语句，不是运行时逻辑。
- **Worker 侧会话清理无自动化守卫**。它是部署期动作，随 `06.1-06` 的生产验收执行。
- `tests/support/strip-comments.ts` 是本票新增的测试辅助；注释剥离沿用仓库既有做法（`deployment-routes.test.ts` 拆 schema 时同样先剥注释）。
- 未新增生产依赖；`esbuild` 是 vite 既有依赖，测试侧直接引用。
- `npm run typecheck`、`npx vitest run`（149 passed / 22 files）、`npm run verify:release` 全部通过。
