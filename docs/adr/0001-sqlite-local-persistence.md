# ADR-0001: SQLite 本机持久化边界

- 状态：已实现（#08）
- 日期：2026-10-04

## 背景

轻盈计划当前通过统一的健康数据仓库使用浏览器 localStorage。下一阶段需要跨浏览器、跨设备的本机持久化，但不能让页面直接操作 SQLite 文件，也不能改变已有健康快照、导入导出和计算规则。

## 决策

使用绑定 `127.0.0.1` 的 Node.js 服务和 `data/vita-log.sqlite`。SQLite 通过 `GET /api/snapshot` 读取完整版本化快照，通过带 `expectedVersion` 的 `PUT /api/snapshot` 原子提交完整快照。SQLite 迁移后成为日常事实来源，浏览器快照只保留为只读迁移副本。

首次迁移先展示来源、各类记录数量、日期范围、设置摘要和 SQLite 是否为空，由本人确认后执行。SQLite 非空时拒绝自动迁移，替换或合并只能通过已有导入流程明确执行。服务不可用时显示错误，不回退写 localStorage。

后端验证本人编辑会话；读取允许本机访问，写入、迁移、备份和恢复需要会话。首次启动设置账号密码，后端只保存加盐密码哈希，会话 30 分钟到期，锁定立即撤销。

本机访问边界由监听层承担：Node 进程绑定 `127.0.0.1`，并在进入 API 处理前拒绝不匹配的 `Host` 头。请求处理层不再维护 `127.0.0.1` hostname 白名单，所有校验改为相对请求自身 origin（`Origin` 与 `Sec-Fetch-Site`），这样同一套 API 语义可以复用到 Cloudflare Pages Functions 所在的公网域名。详见 ADR-0002。

每次破坏性替换前创建当前数据库备份；每日首次写入自动备份，保留最近 30 份每日备份，手动备份不自动删除。恢复先展示摘要并确认，恢复前再备份当前数据。命令行提供本机备份/恢复，依赖操作系统文件权限。

数据版本只支持前向迁移，启动时执行；迁移失败停止写入。版本冲突拒绝过期提交并保留未提交输入。API 使用稳定错误码区分未登录、版本冲突、校验失败、数据库不可用和迁移冲突。

首期不做应用层加密，依赖本机文件权限，并建议使用磁盘加密和受限目录。

## 取舍

完整快照载荷保持现有页面和 JSON/CSV 业务契约，避免把 SQLite 表结构变成第二套领域模型。单一事实来源避免 localStorage 与 SQLite 双写冲突；明确迁移确认避免误覆盖已有数据库。
