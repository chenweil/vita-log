# ADR-0002: Cloudflare D1 实时公开读取与服务端编辑授权

- 状态：已决定，实现中（#06.1-01 读取与公共投影已交付；写路径、会话、备份与公网验收未开始）
- 日期：2026-10-05
- 关联：#06.1

## 背景

原 #06 完成的是手动生成 JSON 的静态只读快照。新的访问模型要求所有访客看到服务端当前已保存数据，只有本人通过密码登录后才能编辑。公网部署优先使用 Cloudflare。

## 决策

- 保留 Vite 静态前端，部署到 Cloudflare Pages；动态 API 使用同源 Pages Functions，在线事实来源使用 Cloudflare D1。
- D1 是唯一在线事实来源。本机 SQLite 迁移完成后仅保留为离线备份/恢复副本，不双写、不做在线镜像。
- 未登录访客可以读取完整健康看板：昵称、体重/体脂、围度、步数、打卡、饮食明细和备注。认证、会话、备份和内部元数据不进入公开响应。
- 未登录状态始终只读。本人通过服务端密码会话后才允许写入；新增、修改、删除、导入、清空、迁移、备份和恢复都由服务端逐请求授权。
- 首个管理员通过部署时 Cloudflare Secret 或一次性运维命令预置，公网不开放初始化接口。密码遗失只通过 Cloudflare Secret/运维命令离线重置。
- Worker 使用 Web Crypto PBKDF2-HMAC-SHA-256、210,000 次迭代和独立盐。会话 30 分钟绝对过期，锁定/注销立即撤销。
- 会话 Cookie 使用 `HttpOnly`、`Secure`、`SameSite=Strict`；写请求强制校验 `Origin/Host`，不开放 CORS。
- 登录和写接口使用 Cloudflare Rate Limiting/WAF 与 Worker 内部按账号/IP 双层限流。写操作只保留时间、操作类型、结果和版本等最小审计事件。
- 健康数据 API 使用 `Cache-Control: no-store`。本人保存成功后，访客下一次刷新读取 D1 最新快照，不做主动推送。
- D1 必须为空才能首次迁移。本机 SQLite 先生成迁移预览，核对数量、类型、日期、汇总和设置摘要，由本人确认后一次性导入；完成对账和备份前不开放公网读取。
- D1 使用平台恢复能力，定期导出完整 JSON 到受限离线备份，同时保留本机 SQLite。D1/Pages Functions 故障时 fail-closed，访客看到明确不可用提示，不回退旧缓存、本机数据或空数据。
- #06 的手动只读 JSON 快照继续保留，但单独标注为非实时分享。

## 取舍

Cloudflare Pages + Pages Functions + D1 与公网访问路径同源，避免独立 API 域名和 CORS 凭据面；D1 迁移牺牲本机 SQLite 作为在线主库的简单性，换取 Cloudflare 上可用的服务端事实来源和实时读取。完整看板公开是产品决策，安全边界由服务端写入授权、初始化保护、会话、限流、CSRF 和 fail-closed 读取共同承担。

## 验收边界

上述决定只完成设计收敛，不代表公网部署已经安全通过。实现后必须在 Cloudflare 预览和生产环境验证匿名读取、未授权写入、会话过期/注销、初始化抢占、CSRF、限流、D1 迁移对账、备份恢复和故障 fail-closed。
