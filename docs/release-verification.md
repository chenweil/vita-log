# 第一版发布验收

这份 runbook 用来区分仓库内可以重复执行的发布检查和必须在目标环境取证的迁移验收。自动检查通过不等于真实托管、真实历史数据或旧页面下线已经完成。

## 本地发布检查

在项目根目录执行：

```bash
npm run verify:release
```

该命令会先执行严格类型检查和生产构建，再在临时 `127.0.0.1` 静态服务器上读取 `dist/index.html` 及其构建资源。它同时确认生产入口没有指向 TypeScript 源文件，运行产物不包含 `window.__SMART_PAGE__`、`globalThis.__SMART_PAGE__` 或旧数据库入口，并验证首页和资源可以通过静态 HTTP 返回。

独立应用的运行时回归由 `npm test` 覆盖：本地存储异常会显示错误页，导入读取失败会显示可操作错误，只读发布页面不加载表单且拒绝仓库写入。桌面和移动视口的真实浏览器检查仍需要在目标浏览器执行。

## 目标静态环境

部署 `dist/` 到 HTTPS 静态托管。目标环境至少需要验证：

1. 首页和构建资源返回 200，刷新深链接不会丢失入口。
2. 不注入 Workbuddy 全局对象时，纯静态模式可以加载本地快照、只读查看并导出数据；编辑流程在 Cloudflare D1 模式单独验收。
3. `?publication=vita-log-publication.json` 可以打开只读发布快照；发布时间可见，页面没有写入入口。
4. 浏览器禁用或破坏本地存储时，页面显示错误和下一步，而不是生成空数据。

记录目标 URL、部署版本、浏览器与视口、检查时间和结果。真实 URL 与个人数据不写入仓库。

## 历史数据迁移

迁移前从腾讯云文档导出文件，并在本人设备上保存原始文件和现有页面的完整 JSON 备份。导入独立应用时按“解析 → 校验 → 预览 → 确认提交”执行；预览记录各类接受、拒绝、重复和冲突数量。

确认后核对以下内容：

- 各类记录总数、最早/最晚日期和代表性日期；
- 代表性日期的饮食热量、蛋白质、脂肪、碳水和钠汇总；
- 体重、围度和步数趋势中的代表性点；
- 导入后重新导出的完整 JSON 可以读取，且包含与页面一致的版本和记录。

把核对结果记录在迁移验收记录中，使用脱敏摘要，不把真实健康数据或原始导出文件提交到 Git。

## Workbuddy 回退与下线

在独立应用和新 JSON 备份完成核验前，旧 Workbuddy 页面只能作为只读回退。核验完成后再移除生产入口；保留旧 HTML 作为参考证据不代表它仍是运行依赖。

## 当前证据边界

仓库可以证明构建、静态资源入口、无 Workbuddy 全局运行路径、错误状态和只读能力。目标托管 URL、真实历史数据对账、迁移后的新备份、旧页面回退窗口以及真实桌面/移动浏览器结果，必须在外部环境完成后再勾选 #07 对应验收项。
